# Vendored Snowball stemmers — provenance

The Python files in this directory are **generated code**, produced by the
Snowball compiler's `-python` backend and vendored here so the indexer's
build-time stems match Pagefind's query-time stems byte-for-byte. Do not edit
them by hand — regenerate with `scripts/generate-stemmers.sh` and re-baseline
the manifest.

## Why vendor instead of depending on `snowballstemmer`

The `snowballstemmer` PyPI package is generated by the same compiler, but no
published release reproduces `pagefind_stem` 1.0.0 across all 14 languages —
both adjacent lines were measured against this package's full corpus:

- **3.0.0.1 / 3.0.1** predate the `english.sbl` fixes the crate has — they
  diverge on **18 English words** (`internal`, `interval`, `interfered`,
  `skis`, …), 0 elsewhere.
- **3.1.0 / 3.1.1** postdate apostrophe/elision changes the crate does NOT
  have (Danish/Norwegian/Finnish apostrophe handling, Italian elisions, German
  apostrophe) — they diverge on **2,103 corpus words** (it 1,867 / fi 183 /
  da 35 / no 18); German diverges on apostrophe words this corpus happens not
  to contain.

Commit `019c1bd` sits between: it *has* the English fix and *lacks* the
apostrophe/elision changes, so it is byte-exact with `pagefind_stem` 1.0.0 over
all 14 languages (589,069 corpus words, 0 divergences). A stem Pagefind cannot
reproduce at query time is a word nobody can find, so parity with what
Pagefind's WASM actually runs beats "newer algorithm". This mirrors
`scolta-php/src/Index/Snowball` (same commit, same parity result).

## Why a mainline commit, not a release tag

`pagefind_stem` 1.0.0 vendors Rust sources generated by the Snowball compiler
from an unpinned snowball checkout (see the crate's own `build.js`). The commit
above is the one whose compiler output is byte-identical to that crate's
vendored algorithm set, recovered in the scolta-php stemmer work by
byte-comparing the compiler's `-rust` output against the crate's sources. Any
commit producing identical output would be an equally valid pin; this one is
verified.

## The version-header trap

Each generated file carries a `Generated from <x>.sbl by Snowball <version>`
header. That string is the **compiler's version at the pinned commit**
("3.0.0" here, since the commit predates the 3.1.0 bump) — it identifies
neither a release tag nor the algorithm state. Never trust the header: verify
the commit hash above, and let the corpus parity tests judge the output (0
divergences over 589,069 words across all 14 languages at this baseline).

## What is vendored, and the (absent) transforms

The 14 `<algorithm>_stemmer.py` files are the compiler's `-python -eprefix _`
output verbatim; `basestemmer.py` (the `BaseStemmer` runtime) and `among.py`
(the `Among` helper) are copied verbatim from `python/snowballstemmer/` at the
same commit. Unlike the PHP port, the Python backend already emits
PSR-clean, floor-compatible code, so **no source transforms are applied** —
the files are byte-identical to the compiler output. `__init__.py` is the
package marker written by the generation script. `scolta.index.stemmer.Stemmer`
maps language codes onto the `<Algo>Stemmer` classes and calls `stemWord`.
